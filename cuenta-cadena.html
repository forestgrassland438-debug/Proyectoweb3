Tables on the contract

Created automatically the first time they are needed, like exp. Only the server can write them: the relay refuses any cta_ table coming from a browser.

Saving fees

Nothing is written if nothing changed. What changes often waits a minimum time between transactions; relations (friends, invites, Lands) are one transaction each; large data goes in batches.

One player

“Restore” never overwrites newer data: counters and experience keep the highest value, states keep the database value, and relations are only restored if the database has none.

Encrypted anchor

Private messages, the Google sign-in wallet records and each account profile, compressed and encrypted (AES-256-GCM) inside the data of one transaction per batch. The contract ignores those extra bytes; the chain keeps them forever.

Disaster recovery

After a database wipe: reads every invoice of the contract (200 per call) and every anchored batch, and rebuilds the accounts. It only fills what is missing. It can take several minutes and uses RPC quota.
